# 製品の原則

Harneloop は採用された製品名です。アーキテクチャは特定のベンチマークやタスク群に依存しません。

<a id="what-this-is"></a>
## この製品について

Harneloop は、エージェントが自分自身または別の対象エージェントを取り巻くハーネスを構築・改善するためのフレームワークです。

フレームワークはエージェントの次の作業を支援します：

- タスクを試行する；
- 実際の成果物を調べる；
- 失敗を実行にさかのぼって追跡する；
- ワークフロー、証拠、環境の前提、未解決の疑問を含むユニット内の運用マップを維持する；
- 操作エージェントの能力不足を、ユニットや対象エージェントのツールと分けて特定する；
- 適切な既存ツール、スキル、ライブラリ、データセット、例、過去の成果を調査・再利用する；
- ハーネスの候補パッチを提案する；
- 候補パッチをテストする；
- 証拠に裏付けられた改善だけを昇格する；
- ポータブルなハーネスユニットをパッケージ化する。

<a id="what-this-is-not"></a>
## この製品ではないもの

Harneloop は次のものではありません：

- 汎用評価ダッシュボード；
- 固定的なエージェントグラフのフレームワーク；
- Blender 専用のシステム；
- モデルの学習やファインチューニングのシステム；
- ライフサイクルを持たない単なるプロンプトのフォルダ。

<a id="core-design-tension"></a>
## 設計の主要な両立課題

システムは生成 AI モデル向けなので、推論と探索の余地が必要です。同時に、フレームワークはライフサイクルの整合性を守る必要があります。

ルール：

> エージェントは候補内で自由に探索できます。昇格はエンジンが制御します。

`operational-map.md` は、ハーネスユニットについてのエージェントの現在の理解を、固定スクリプトにせず保存します。エージェントはこれを使って状況を把握し、証拠の変化に合わせて更新し、現在のタスクと成果物に基づいて推論を続けてください。

ハーネスユニットを構築するエージェントが万能だと想定してはいけません。操作エージェントに不足する能力を特定し、証拠や明確な改善見込みで必要性を示し、ツール、依存関係、認証情報、有料サービス、広範な外部アクセスを追加する前に適切な許可境界を守ってください。

Harneloop は、すべての能力をゼロから作り直すのではなく、検証済みの最良のタスク性能を目指します。操作エージェントは既存の解決策を調べ、ハーネスを改善するなら採用、適応、組み合わせ、学習を行えます。再利用は検証可能にしてください。何をなぜ使ったか記録し、互換性と実際の価値を確認し、ライセンスと帰属表示を守り、セキュリティ、認証情報、外部アクセス、費用、大きなインフラ変更には通常の許可手続きを適用します。
