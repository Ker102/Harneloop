# 並行処理とファイルの安全性

エージェントは Harneloop コマンドを短い間隔で連続実行したり、並行実行したりします。制御ファイルを読み、連番 ID を計算して書き戻すコマンドは、読み取り・変更・書き込みの全体を保護する必要があります。

<a id="current-rule"></a>
## 現在のルール

- 共有ライフサイクル処理にはハーネスユニットのロックファイルを使います。
- ロック内で対象の YAML または JSON ファイルを読み直します。
- ロック内で次の連番 ID を割り当てます。
- 一時ファイルのアトミックな置換で YAML と JSON を書き込みます。
- ファイル更新が完了してからロックを解放します。

<a id="implemented-locks"></a>
## 実装済みのロック

- `runs`：実行 ID を割り当てます。
- `run-<id>`：成果物を追加し、実行を終了します。
- `attempts`：試行 ID を割り当てます。
- `attempt-<id>`：試行の観察を追記します。
- `candidates`：候補 ID を割り当てます。
- `candidate-<id>-evidence`：証拠 ID を割り当てます。
- `lifecycle`：候補を昇格し、バージョンをロールバックします。
- `state`：`.evolve/state.json` と派生状態ファイルを更新します。

ロックは `.evolve/locks/` に保存されます。これはフレームワークが管理する実行時状態で、ポータブルパッケージには含まれません。

<a id="rust-runtime-note"></a>
## Rust ランタイムについて

現時点では Rust は不要です。アルファ版 CLI には Python のファイルロックとアトミック置換で十分です。製品の機能面が安定した後、将来の Rust ランタイムが、より厳密なサンドボックス化、プロセス監視、より確実な並行ファイル調整を担う可能性があります。
