# コアライフサイクル

<a id="harness-unit"></a>
## ハーネスユニット

ハーネスユニットは、再利用可能なハーネス素材とフレームワーク制御ファイルを含むポータブルなディレクトリです。

必須ファイル：

```text
unit/
  unit.yaml
  UNIT_AGENT.md
  operational-map.md
  candidates/
  versions/
  provenance/
```

`operational-map.md` はユニット内の状況把握文書です。改善対象、対象環境の使い方、有用な成果物や証拠、通常の実行・リセット方法、操作エージェントの能力不足、ユニットや対象エージェントのツール、既知の脆弱な箇所、前提、未解決の疑問、過去の証拠の場所について、エージェントの現在の理解を記録します。固定手順にせず、エージェントを案内するものです。

一般的な任意フォルダ：

```text
agent-facing/
observers/
validators/
regression-cases/
infrastructure/
exports/
tools/
memory/
experiments/
```

<a id="candidates"></a>
## 候補

候補はまとまりのある変更群または仮説であり、1 回のファイル編集や Git コミットではありません。一緒にテスト・昇格すべき関連する設定、ツール、指示、バリデーターの変更は 1 つの候補に蓄積できます。対象ハーネスの改善と独立した評価修正など、別々の問題には複数候補を開いたままにできます。

```text
candidates/cand-0001/
  candidate.yaml
  rationale.md
  changes/
  validation/
  evidence/
  notes.md
```

候補変更はフレームワークを通じて適用します。候補オーバーレイは `unit.yaml`、`versions/`、`provenance/`、`.evolve/`、`candidates/` などの保護されたパスを編集できません。

現在の各候補は次を宣言します：

- 影響する領域：`target_harness`、`evaluation`、`infrastructure`、`mixed`；
- 検証レベル：`structural`、`targeted`、`representative`、`full`；
- ライフサイクル段階：`accumulating`、`ready`、`validating`、`needs_rebase`、`promoted`、`rejected`；
- ベースとなる昇格済みハーネスのバージョン。

検証はリスクに比例させます。メタデータのみの変更は構造チェック、独立したインフラや評価器の修正は対象を絞ったチェック、ハーネスの動作変更は代表的な実行が適します。完全な回帰テストは広範な変更とリリース時の確認に使います。より強いレベルを選べますが、設定の小さな変更ごとに成果物ベンチマーク全体を実行するべきではありません。

評価と対象ハーネスの変更は通常別候補にし、変更済みの評価器だけをハーネス改善の証明にしないでください。関連作業をまとめる間は `accumulating` のままとし、検証できる程度にまとまってから `ready` に進めます。

<a id="promotion"></a>
## 昇格

昇格は、準備できた候補オーバーレイをユニットに適用し、`versions/` に復元可能なスナップショットを作成し、来歴を更新します。候補作業が並行でも、昇格済みバージョンは直線的な系列です。

同じベースを持つ候補が 2 つある場合、片方の昇格によって他方は `needs_rebase` になります。ファイルと履歴は保たれますが、昇格前に新しい版との整合を取り、新しい証拠を集める必要があります。過去の証拠は来歴として残り、新しいベースの条件を満たすものにはなりません。

証拠参照は添付時と昇格時に整合性を確認します。宣言した実行と成果物が存在し、成果物の保存ファイルが残り、直接参照した証拠ファイルも存在する必要があります。文章による証拠ではこれらの参照を省略できます。

<a id="run-integrity"></a>
## 実行の整合性

実行は `running` 状態の間だけ変更可能で、その期間に成果物を添付できます。最初に成功した `run finish` の遷移で終了状態となります。それ以降の成果物追加や再終了は拒否され、元の結果の無断書き換えを防ぎます。

<a id="rollback"></a>
## ロールバック

ロールバックは以前の昇格済みスナップショットを復元します。手作業のコピーではなく、来歴を伴うフレームワーク操作として行います。

<a id="wait-and-stop"></a>
## 待機と停止

実行ライフサイクルは明示的な待機と停止をサポートします。

待機は成果物の遅延、人によるレビュー、ジョブの待ち行列、クールダウン、インフラ再構築に対応します。

停止は十分な証拠、改善の頭打ち、能力限界の問題、許可の必要性、次の有用な手順が人や外部システムに依存する場合に対応します。

成果物に基づく進化ループの全体は [Harneloop の仕組み](../framework-process.md) を参照してください。
