# Terminologie

<a id="selected-term"></a>
## Terme retenu

L’objet portable de harness est appelé **unité de harness**.

Une unité de harness est un espace de travail Harneloop autonome avec fichiers de contrôle, instructions destinées aux agents, candidats, versions, contrats d’environnement, enregistrements d’exécution et exports.

<a id="why-this-name"></a>
## Pourquoi ce nom

`Harness unit` est plus clair que `unit`, car sa finalité reste visible partout où le terme apparaît. Il reste aussi neutre vis-à-vis du framework dans les workflows visuels, de code, de recherche, d’automatisation et d’agents applicatifs.

<a id="usage"></a>
## Utilisation

Utilisez **unité de harness** dans les textes destinés aux utilisateurs, la documentation, les menus, les prompts et les instructions des agents.

Conservez pour l’instant les noms de commandes tels que `harneloop init-unit` et `harneloop units` pour éviter les modifications inutiles. Ces commandes gèrent les unités de harness.

Évitez `unit` seul dans les textes destinés aux utilisateurs, sauf si la phrase rend déjà le sens évident.
